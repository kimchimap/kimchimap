## 일반음식점 확정 계약

공식 페이지에 내장된 Swagger를 2026-09-07 확인했다. `https://apis.data.go.kr/1741000/general_restaurants/info` GET을 사용하며 `serviceKey`, `pageNo`, `numOfRows`(최대 100), `returnType=json`을 전송한다. Decoding 키를 URI 경계에서 한 번 인코딩한다. 확인된 증분 필터는 `cond[DAT_UPDT_PNT::GTE]`와 `cond[DAT_UPDT_PNT::LT]`이며 요청 형식은 YYYYMMDDHHMMSS다. `/history`는 BASE_DATE와 지자체 코드가 필요한 별도 계약이라 현재 수집기에 사용하지 않는다.

보관 필드: OPN_ATMY_GRP_CD, MNG_NO, BPLC_NM, ROAD_NM_ADDR, LOTNO_ADDR, SALS_STTS_CD/NM, DTL_SALS_STTS_CD/NM, CRD_INFO_X/Y, DAT_UPDT_PNT, LAST_MDFCN_PNT, CLSBIZ_YMD, TELNO. 원천 ID는 지자체 코드와 관리번호 조합이다. TELNO는 공개된 업소 연락처로 제공하며 개인 연락처를 별도로 탐색하지 않는다. 불필요한 추가 응답 필드는 버린다. 원산지·표시판 검증 필드는 없다.

응답은 response.header.resultCode 문자열 `0`, body.totalCount/pageNo/numOfRows 숫자와 items.item 배열이다. 실제 첫 조회에서는 날짜가 `yyyy-MM-dd HH:mm:ss`로 반환되어 공식 안내의 압축 형식과 함께 지원한다. 시각의 타임존이 명시되지 않아 행정 자료의 한국 현지 시각으로 해석한다. 이 가정과 원천 시차를 실제 원산지 관찰 시각으로 사용하지 않는다.

공식 페이지의 무료·이용허락범위 제한 없음 표시를 수집·저장·재게시 근거로 기록한다. 조회 내용에는 출처 기관명을 표시한다. 개발 트래픽 10,000회 표기를 준수하도록 기본 페이지 간격 1초·자동 일일 페이지 예산 1,000을 둔다. 실제 권한별 한도는 포털 승인 설정을 확인하며 429와 Retry-After를 처리한다. 별도 초당 한도는 확인되지 않았다. fixture는 공식 필드 구조에 맞춰 작성한 명시적인 가상 업소이며 실제 응답 복제본이 아니다.

## 목적 적합성 재조사 · 2026-09-08

- 일반음식점 공식 설명·기존 Swagger 계약 모두 원산지 필드가 없다. 신규 국내산 업소 발굴용으로 사용하지 않는다. 추후 이미 국내산 자격을 확보한 업소의 기본정보 보완도 실제 선택 조회 명세가 확인될 때 별도 설계한다. 이를 위해 전체 업소 수집을 재개하지 않는다.
- [협회 지정 기준](https://koreakimchiself.org/sub/com/com01.asp?pageNum=1&scrID=0000000145&ssubNum=1&subNum=1): 일반 음식점의 국산 재료 김치와 고속도로 휴게소의 95% 이상 국산 재료 기준을 구분한다. 지정만으로 모든 부재료의 개별 국가 기록을 생성하지 않는다. 실제 적용 품목과 예외를 확인해야 한다.
- [협회 약관](https://koreakimchiself.org/policy/policy01.asp?scrid=0000000162): 자동 수집·저장·재게시를 명시적으로 허용한 근거는 확인하지 못했다. 사용자도 별도 허가 없음 확인. 웹 조회 가능 여부와 재사용 허가는 별개다.
- [농관원 원산지 인증 안내](https://www.naqs.go.kr/goodfood/portal/certification/origin2.jsp): 제도 기준 설명이며 현재 확보한 업소별 국내산 목록·API가 아니다. 같은 원산지 사용 요건을 국내산으로 해석하지 않는다.
- 공공데이터포털·지자체 검색에서 발견한 급식 식단 원산지는 일반 이용자가 방문하는 음식점 자료와 범위가 달라 채택하지 않았다. 검색에서 적합한 자료를 아직 확인하지 못했다는 뜻이며 전국에 자료가 전혀 없다고 단정하지 않는다.
- 승인된 이용자 제보가 현재 직접 확보 가능한 원산지 입력 경로다. 미등록 업소→사진·항목 제보→관리자 검수→국내산 자격 확인→공개 흐름을 구현한다.
