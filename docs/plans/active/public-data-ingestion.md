# 공공데이터 수집 구현

- 목표: 확인한 일반음식점 API의 실제 수집·정규화·저장·재실행·상태 조회를 구현한다.
- 범위: 공식 /info 클라이언트, 계약 테스트, 제한 호출·오류/재시도·페이지/checkpoint·DB lease·원천 ID 멱등 저장·정정 보호·증분/대조·로컬 명령. 관리자 HTTP 인가는 P06/P07과 연결한다.
- 수용 기준: 키 없이 계약/실제 DB 테스트 실행, 실제 키로 제한 범위 수집 후 공개 상세/검색 확인, 개인정보 최소화, 원산지 정보 미생성, 중복 실행/페이지 부분 실패/변경/429/잘못된 좌표 테스트.
- 현재 브랜치: feat/public-data-ingestion
- 기준 dev: ee0f1f0f57c2f19f759c3c1345903f47046aa802
- 완료: PR #4 병합·이전 브랜치 정리, 공식 내장 Swagger와 실제 2건 조회 확인.
- 추가 사용자 요구: 공공 API TELNO는 업소 연락처로 저장·공개하고 전화 연결을 제공한다. 미기재/잘못된 형식은 버튼 미표시. 대표자 개인 연락처를 별도로 찾지 않는다.
- 명세 차이: 문서는 갱신 시각을 YYYYMMDDHHMMSS로 안내하지만 실제 2건 응답은 yyyy-MM-dd HH:mm:ss다. 두 형식을 명시적으로 지원하고 다른 형식은 격리한다.
- 완료한 구현: 공식 응답 클라이언트와 계약 테스트, 원천 기록·작업 lease·체크포인트·정규화·수집 명령·스케줄러를 작성했다. 실제 PostGIS 수집 통합 테스트 4개가 통과했다. 정정 보호·전체 대조·페이지 쓰기 롤백 추가 검증과 실제 외부 연동은 남아 있다. 업소 전화번호 저장·공개 권한 검사와 연락처 화면(`/restaurants/:id/contact`)을 추가했다.
- 남은 작업: 수집 전용 DB 통합 테스트·실연동·전체 검증·문서·PR. 전체 상세 화면 동선은 P08과 연결한다.
- 외부 조건: 키·카카오 설정·공공 API 활용 승인 확인. 협회 자동 수집·재게시 허가는 미확인. 원산지 데이터는 없음.
- 다음 작업: 수집 전용 DB 테스트에서 페이지 재개·멱등·정정 보호·실패 원자성·동시 임대 검증, 실제 제한 범위 수집 후 전화번호를 포함한 공개 조회 확인.

- 전화번호 검증: frontend 테스트 9개, 타입·린트·빌드·API 계약 일치, 업소 상세 DB 테스트 11개 및 수집 DB 테스트 4개 통과. 증거는 docs/validation.md에 기록했다. 아직 미커밋이며 P05 전체 검증 후 PR로 병합한다.
