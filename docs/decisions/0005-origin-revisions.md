# 원산지 기록과 공개 조회의 경계

2026-09-07. 업소·scope·근거·원산지 revision은 UUID를 사용한다. 외부 식별자는 별도 source/id 유일 키로 보존한다. 승인된 원산지의 정정은 새 revision과 명시적 철회로 표현하고 원문·국가·관찰일을 수정하지 않는다.

V2는 원산지 구성 행의 분류·개수·비율을 지연 제약 트리거로 커밋 때 검증한다. 일반 CHECK는 다른 행을 조회하는 용도로 사용하지 않는다. 구성은 부모 revision을 생성한 동일 DB 트랜잭션에서만 추가할 수 있으며 이후 UPDATE/DELETE는 거부한다. xid8 생성 트랜잭션 열은 API에 노출하지 않는다. 앱 계정은 DML만 가지므로 트리거를 우회할 DDL 권한이 없다. 관리자가 사용하는 백업 복원 절차에서는 스키마 소유자 권한과 트리거 재구성을 검증해야 한다.

공개 상세는 읽기 전용 SQL projection을 한 REPEATABLE READ 트랜잭션에서 조회한다. scope·claim·component·designation을 각각 일괄 조회하여 N+1을 피한다. scope 200개, claim 2,000개, 지정 200개를 넘으면 일부 주장을 누락한 채 정상 원산지로 판정하지 않고 명시적인 422를 반환한다. 향후 상세 페이지 분할은 판정에 필요한 전체 후보와 표시 페이지를 분리해야 한다.

승인 기록 전체를 판정하되 공개 허용된 근거만 응답한다. 비공개 승인 기록의 상충을 숨겨 국내산으로 통과시키지 않는다. 현재 상세는 결정적 정책으로 조회 시점의 만료·철회를 평가한다. publication과 이력 테이블은 관리자 승인·정정(P07)의 원자적 공개 반영과 검색(P04)에서 사용할 구조다. 이 작업에서 관리자 해결 절차를 완료했다고 보지 않는다.

국가·식재료 카탈로그는 확장 가능하며 초기 데이터는 한국·중국·미국·호주·베트남과 주요 식재료 6종이다. 세계 전체 국가 목록이나 실제 원산지 확보 범위를 뜻하지 않는다. 법정 표시 규칙은 공식 출처와 적용 범위를 확인한 후 등록하며 현재 초기값은 없다. 인증·지정은 독립 테이블이며 식재료 원산지로 자동 변환하지 않는다.
