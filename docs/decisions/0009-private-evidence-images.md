# 비공개 증빙 이미지와 즐겨찾기

확인일: 2026-09-07. [JDK ImageReader](https://docs.oracle.com/en/java/javase/25/docs/api/java.desktop/javax/imageio/ImageReader.html), [OWASP 업로드 지침](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)을 참고했다.

초기 허용 형식은 JPEG·PNG다. JDK의 실제 디코더로 형식과 선언 MIME·확장자를 비교한다. WebP는 추가 디코더의 보안·호환성을 확인하기 전까지 거부한다. 기존 설계의 WebP 예정 범위를 축소한 것이며 테스트 실패 회피를 위한 변경은 아니다. 원본 10MiB, 각 변 8192픽셀, 총 20MP, 정제 결과 20MiB로 제한한다. 디코딩 전에 크기를 읽어 과대 이미지를 차단한다. 경고가 발생한 손상 파일도 거부한다.

원본 메타데이터를 복사하지 않고 새 BufferedImage의 픽셀로 재인코딩한다. 정제는 개인정보 가림과 다르다. 얼굴·전화번호 등 이미지에 보이는 정보는 관리자 검토가 별도로 필요하다. 파일명은 저장 경로에 사용하지 않으며 무작위 UUID 키만 사용한다. 경로는 웹 루트 밖이며 저장소 루트의 심볼릭 링크와 파일 링크 읽기를 거부한다. POSIX 디렉터리 700·파일 600, CREATE_NEW로 기존 파일을 덮어쓰지 않는다. 원본·정제본 모두 소유자/관리자만 인증 API로 조회하고 no-store·nosniff·고정 다운로드 이름을 사용한다.

Security 뒤·multipart 파싱 전 동시 업로드를 2개로 제한한다. 디코더도 최대 2개 작업이며 대기열을 쌓지 않는다. 처리 응답 제한은 10초, 중단 후 디코더가 즉시 종료되지 않더라도 실행 슬롯을 추가하지 않는다. 이 제한은 별도 프로세스의 강제 종료나 측정된 전체 메모리 보장을 의미하지 않는다. 사진 요청은 사용자별 시간당 10회이고 실패도 계산한다. Redis 장애는 인증·제한 확인을 통과시키지 않는다.

DB와 파일시스템은 같은 트랜잭션이 아니다. 파일 기록 성공 후 DB 응답을 잃으면 커밋 여부가 불명확하므로 파일을 바로 삭제하지 않는다. 7일 지난 고아 파일은 DB 참조가 없음을 재확인한 뒤 정리한다. 제출에 연결되지 않은 TEMPORARY 파일은 24시간 후 DELETING으로 원자 전환하고 삭제한다. ATTACHED 전환과 경합하면 DB 상태 조건으로 보호한다. 삭제 중 실패는 DELETING을 유지해 재시도한다. 기본 정리는 한 시간 간격, 실행당 100개다. 원본의 장기 보존 정책은 공개 운영 전 확정한다.

미디어 공개·제보 연결은 P07b의 검수 트랜잭션에서만 추가한다. 이번 단계는 원본/정제본을 공개하지 않는다. 업로드 ID를 타인 제보에 연결할 수 있다고 간주하지 않는다.

즐겨찾기는 회원·업소 복합 키로 중복을 방지한다. PUT/DELETE는 멱등이며 다른 회원의 userId를 받지 않는다. 공개된 업소만 추가·조회하고 최대 50개, 저장 시각/업소 ID로 안정 정렬한다. cursor는 본인 즐겨찾기를 기준으로만 해석한다. 삭제·추가 사이의 페이지는 엄격한 snapshot이 아니므로 최신 목록을 다시 불러올 수 있다.
